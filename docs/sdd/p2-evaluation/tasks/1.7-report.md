How the closing run is cut, in `_heading_title`:
1. `strip(" \t")`. The old regex had a greedy `[ \t]+` before the group, and its lazy group stopped before trailing spaces and tabs, so the old title had neither.
2. `body = text.rstrip("#")`. When `body` is empty (the content was only `#`s), or ends in a space or tab, the run was a closing sequence, and the text becomes `body.rstrip(" \t")`. Otherwise the `#`s belong to the title (`foo#`).

Why it is linear:
- **Closing run.** Each step is one pass over the line.
- **New `HEADING`.** It has no alternative to retry. `[ \t]+` and `.*` both run to the end of the line, and `$` matches on the first try. Lines are split on `\n` before the match, and `.` matches every other character, so `.*` never stops early.
- **New `HTML_TAG`.** It still cannot cross a `<`, so each character is scanned from at most one opener, as in 1.6.

The order in `_heading_title` is: the closing run, then tags, then the `{#id}` block, then strip. So `## Title {#id} ##` still gives `Title`.

## Limitations

- A backslash-escaped closing `#` is not unescaped, as before. `### foo \###` gives the title `foo \###`; CommonMark gives `foo ###`.
- `HTML_TAG` still removes anything that looks like a tag, even when the heading text is not markup. `` ## The `<div>` element `` becomes ``The `` element``, and `## a <b> c` becomes `a  c`, as noted in 1.6. A comment or tag containing `<` or `>` (`<!-- a > b -->`) is only partly removed.
- A document that is already ingested keeps its old path until it is uploaded again. This applies to a heading like `### ###` (stored as `###`) and a heading with `<` (stored with the span cut out).
