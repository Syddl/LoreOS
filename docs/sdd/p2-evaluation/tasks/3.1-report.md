## Old vs new

| Behaviour | Before | After |
|---|---|---|
| `npm run paid:eval` | no script | Runs `python -m loreos.evaluation`: the preflight, then `run.evaluate(mode, limit, sha)` with the preflight's sha. Prints the result path, its destination, each note and each metric. Exit 0 once a result is written, whichever directory it went to. |
| `--dry-run` | none | Runs only the preflight, prints `dry run: preflight only, no paid call made`, exit 0. `npm_config_dry_run=true` (from `npm run paid:eval --dry-run`, without `--`) is also a dry run. This holds with other arguments too, since a dry run is the safe reading. |
| npm-swallowed flags | none | When `npm_config_limit` or `npm_config_mode` is set, the CLI exits 2 before any preflight. It prints that npm took the flag and the form to use instead: `npm run paid:eval -- --limit N` or `npm run paid:eval -- --mode vector`. |
| Arguments | none | argparse with prog `npm run paid:eval --`. It takes `--mode {vector}` (from `run.MODES`), `--limit N` and `--dry-run`. `--limit` must be an integer of at least 1, else exit 2 with `'0' is not an integer of at least 1`. An unknown argument or mode exits 2. `-h`/`--help` prints usage and returns 0 without the preflight. |
| Preflight order | none | It stops at the first failure with `SystemExit("preflight: ...")`. Each problem is listed on its own line with its fix. The order:<br>1. `questions.jsonl` exists (else it is named, pointing at `eval/README.md`), reads as JSON lines, and passes `question_problems`.<br>2. The calibration file, when present, reads and passes `calibration_problems`.<br>3. `manifest_problems`.<br>4. `fetch.corpus_problems` (each problem says to run `npm run eval:fetch`).<br>5. No two manifest files share a sha256; both files are named.<br>6. Every corpus file parses (named when not).<br>7. `label_problems`, which names the closest heading.<br>8. `smoke.preflight()`.<br>9. One `models.list()`: each of `EMBEDDING_MODEL`, `ANSWER_MODEL` and `JUDGE_MODEL` must be listed, and every missing one is named as `VAR=model`. An `APIStatusError` prints that the names are unverified and goes on. Any other `OpenAIError` stops.<br>10. `run.tree_clean()`, unless `--limit` is given. |
| Plan | none | Five `plan:` lines, then one `warning:` per `labels.broad_labels` entry:<br>- questions run of the total, with answerable and unanswerable counts;<br>- the workspace name, `reused` or `to build`, and the corpus embedding tokens and embed calls. Both are 0 when reused. Otherwise tokens are the exact sum of `count_tokens(embedding_input(c))` over every file's chunks, and calls are `ceil(chunks / EMBED_BATCH)` per file, as ingest batches them;<br>- total embed calls (corpus plus one per question);<br>- answer calls up to the questions run, and judge calls up to answers plus the calibration rows (0 with `--limit` or without the file);<br>- input tokens up to about `TOP_K * CHUNK_TOKENS + 1000` per answer or judge call, and the total. Output tokens are said to be uncapped. |
| `eval:fetch` outline | `main` downloaded and verified only | Once every file is good, `main` writes `eval/corpus/outline.txt` with `labels.render_outline` (UTF-8, LF) and prints its path and section count. A file that does not parse is a problem naming it: exit 1 and no outline. A failed download also writes no outline. |
| Stale corpus file | A present file with the wrong hash stayed when its re-fetch failed | The file is removed after an HTTP error, a network error or a hash mismatch on re-fetch, so no unverified bytes stay at that path (spec behaviour 1). |

## Limitations

- The answer and judge figure is an estimate, not a bound. Chunks are counted with cl100k, while the chat models use their own tokenizer. The 1000-token allowance per call covers the instructions, the question, the source labels and, for the judge, the answer. Output tokens, including the judge's reasoning, have no cap, and the plan says so.
- The corpus token count is exact for a new workspace. For a workspace that exists but is not complete, it is an upper bound: ingest skips the files already `processed`, and the plan counts every file.
- A dry run on a workspace that is not reused parses the corpus twice, once for the outline and once for the plan. That takes a few seconds on the real corpus.
- The calibration file is validated even with `--limit`, as spec behaviour 4 lists it. So between `eval:calibration-draft` and the grading, a `--limit` run is refused until every row is graded.
- `npm_config_dry_run=true` makes any invocation a dry run, also one with arguments. The brief named only the no-argument case. With arguments, the other reading would start a paid run that the operator asked to be dry.
- `outline.txt` is not removed when a later fetch fails: it stays from the last good fetch. The preflight re-checks the corpus and the labels on its own, so a stale outline cannot let a run through.
- `npm run check:all` was not run; the main session runs it once for the phase.
