## Old vs new

| Behaviour | Before | After |
|---|---|---|
| `loreos.evaluation` package | did not exist | exists; `__init__` imports nothing |
| Paths and counts | nowhere | `dataset.{ROOT, EVAL_DIR, QUESTIONS, CALIBRATION, MANIFEST, CORPUS_DIR, RESULTS_DIR, SCRATCH_DIR}` and `CALIBRATION_ROWS = 30`, `MIN_QUESTIONS = 60`, `MAX_QUESTIONS = 100`, `UNANSWERABLE_RANGE = (10, 20)`. `ROOT` is `Path(__file__).resolve().parents[3]`. |
| Reading a `.jsonl` file | nothing | `read_jsonl` reads UTF-8 (a BOM is tolerated), skips blank lines, splits on `\n` only (a raw U+2028 inside a JSON string stays whole), and raises `DatasetError("<path>:<line>: <what>; <fix>")` for bad JSON, a non-object line or non-UTF-8 bytes |
| Reading the manifest | nothing | `read_manifest` returns the object, or raises `DatasetError` naming the path and the JSON error line |
| Evaluation set rules | none | `question_problems` returns one string per problem, each naming the row id (or `row N` when the id is unusable), the rule and the fix. The rules: <br>- `id` and `question` are non-empty strings; `answerable` is a bool; `sources` is a list; `note`, when present, is a string. An unknown key is a problem, in a row and in a source. <br>- Ids are unique. <br>- The unanswerable count is within `UNANSWERABLE_RANGE`, inclusive. <br>- Answerable rows have at least one source, and unanswerable rows have none. <br>- A source's kind comes from `parsing.kind_of(file, b"")`. A Markdown source needs a non-empty `heading_path` list of non-empty strings and no `page`. A PDF source needs an int `page >= 1` (a bool is refused) and no `heading_path`. A `.txt` or unsupported file cannot be labeled. <br>- The 60 to 100 total is not checked here (it is task 2.1's destination rule). |
| Calibration file rules | none | `calibration_problems` requires exactly `CALIBRATION_ROWS` rows and unique ids. `id`, `question` and `answer` must be non-empty strings. `passages` must be a non-empty list of `{n: int >= 1 (not bool), source: str, text: non-empty str}`. `human` must be `faithful` or `unfaithful`: a null or missing grade gives `<id>: not graded yet; grade it, ...`. Unknown keys are problems in a row and in a passage, so a copied `judge` field is refused. |
| Manifest rules | none | `manifest_problems` requires a non-empty `sources` list, each source with non-empty string `name`, `home`, `license`, `attribution` and `files`. `files` must be a non-empty list, and each entry needs: <br>- a relative `file` with forward slashes, no leading `/` and no `..` segment; <br>- an http(s) `url`; <br>- a 64-character lowercase hex `sha256`. <br>Each `file` is unique and falls under exactly one source's `files` prefix (string prefix). |
| Hashes | none | `text_hash(path)` is the sha256 of the bytes after `\r\n` becomes `\n`. `corpus_hash(manifest)` is the sha256 over `"".join(f"{file}\t{sha256}\n")` sorted by `file`. |
| Committed files | unchecked | `eval/questions.jsonl`, `eval/judge_calibration.jsonl` and `eval/corpus.json` are each validated when present. When absent, the test skips, naming the file and who writes it. The real `eval/corpus.json` (48 files, 3 source prefixes `handbook/`, `pdf/nist-`, `pdf/osha-`) validates with no problem. |

## Limitations

- A heading path element must be a non-empty string, as the brief requires. Task 1.6 keeps a heading that cleans to nothing in the path as `""`, so a section under such a heading cannot be labeled. If one turns up in the corpus, `outline.txt` shows it, and this rule then needs relaxing to "strings, not all empty".
- Calibration rows and passages refuse unknown keys. If the operator adds a `note` while grading, the row is refused and the message names the allowed keys. Allowing an optional `note` would be a one-word change to `CALIBRATION_KEYS`.
- A source prefix match is a plain string prefix, as the spec says. `pdf/nist-` covers `pdf/nist-anything`, so it does not stop at a path segment.
- The manifest does not refuse unknown keys. The brief did not ask for that, and the required-key rules catch a misspelled required key.
- `read_jsonl` and `read_manifest` let `FileNotFoundError` propagate, so each caller decides what a missing file means.
