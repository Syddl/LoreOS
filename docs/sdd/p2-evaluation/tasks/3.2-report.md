## Old vs new

| Behaviour | Before | After |
|---|---|---|
| Choosing the calibration rows | none | The eligible rows are the result's `questions` rows with `answer.found` true, sorted by id. The draft picks `dataset.CALIBRATION_ROWS` of them at index `i * (len - 1) // (CALIBRATION_ROWS - 1)`. That picks the first and the last eligible row, and the step is at least 1, so no row is picked twice. With 40 eligible rows, the gaps between picks are 1 or 2. |
| Row shape | none | `{id, question, answer, passages, human}`, in that order. `answer` is `answer.text`. `passages` is `[{n, source, text}]` from `answer.citations`, under their original `n`, which is the input `llm.judge` takes. `human` is `null`. The judge's grade, rationale and error are never copied. |
| Too few answered rows | none | `draft` raises `ValueError`: `the result has <k> answered rows and the draft needs 30; draft from a full run 1 (npm run paid:eval with no --limit)`. `main` prints it after the path and exits 1, writing nothing. |
| Arguments | none | Anything but exactly one argument prints `usage: npm run eval:calibration-draft -- <result file>` on stderr and exits 2. |
| Relative result path | none | It resolves against `INIT_CWD` when that is set and non-empty, else against `dataset.ROOT`. The process cwd is never used, since `uv --directory backend` makes it `backend/`. An absolute path is used as given. |
| Existing calibration file | none | When `dataset.CALIBRATION` exists, `main` exits 1 before reading the result. The message names the file and says to move it aside, because it may hold grades. The write itself opens with mode `"x"`, so a file that appears between the check and the write is not replaced either. |
| Unreadable result file | none | A missing file, invalid JSON or non-UTF-8 text exits 1 with `cannot read <path> (<error>); pass the result file of a full npm run paid:eval`. |
| Output | none | JSONL, one object per line, UTF-8 with `ensure_ascii=False` and LF endings. stdout gives `wrote 30 ungraded rows to <path>`, then the next step: set each row's `"human"` to `"faithful"` or `"unfaithful"`, judging only from its passages, then run `npm run paid:eval`. |
| Entry point | none | `python -m loreos.evaluation.calibration` calls `sys.stdout.reconfigure(errors="replace")`, then `sys.exit(main(sys.argv[1:]))`. `dataset.CALIBRATION`, `ROOT` and `CALIBRATION_ROWS` are read at call time. |

What the tests cover, against the plan's acceptance list:

- **The spread.** 40 answered rows and 10 refused rows are listed in reverse id order, with the refused ids between the answered ones. The draft gives 30 unique ids, sorted. They include the first and the last answered id, and the gaps between picks are exactly `{1, 2}`.
- **Refused rows.** With 30 answered and 20 refused rows, the draft is exactly the 30 answered ids.
- **No judge field.** Every answered fixture row carries `judge: {grade: "unfaithful", rationale: ...}`. No drafted row has a `judge` key, `human` is `None`, and neither `unfaithful` nor the rationale appears in the row's JSON.
- **The row shape.** One row is compared whole: the question, the answer text, and passages `[{n: 1, ...}, {n: 3, ...}]` with their original numbers. The key order equals `dataset.CALIBRATION_KEYS`.
- **The written file.** `main` exits 0 and writes 30 lines, LF only, with a trailing newline and raw UTF-8 `café`. `dataset.read_jsonl` reads back exactly what `draft` returns. stdout names the file and the `"faithful"` / `"unfaithful"` grading step. Once every `human` is set, `dataset.calibration_problems(rows) == []`, which is the shape the validator and `llm.judge` take.
- **No overwrite.** An existing file with CRLF bytes gives exit 1, the same bytes, and the file named on stderr.
- **Too few rows.** 29 answered rows give exit 1, no file, and `29` and `run 1` on stderr.
- **Bad input.** A missing result file gives exit 1, naming it, and no file. Zero or two arguments give exit 2 with the usage line.
- **Relative paths.** `scratch/run1.json` resolves under `INIT_CWD` when it is set, and under the patched `dataset.ROOT` when it is not. The process cwd is moved to a directory without that file in both cases.

**Mutation for the main session's `redproof`.** Run it after the cherry-pick. It copies the judge grade into each drafted row. The find text occurs exactly once in the committed `calibration.py` and has no quote or backslash; the replace text uses single quotes only. It was applied by hand with the edit tool before committing. It gave `3 failed, 9 passed`: the expected test, the whole-row shape test and the validator test, which reports `unknown key 'judge'`. It was then reverted to green.

What these tests do NOT exercise:

- A result file written by a real run: the fixture follows the row shape `run._row` writes, built by hand.
- `npm run eval:calibration-draft` itself, and npm setting `INIT_CWD`. Task 3.1 owns the script; the tests set the variable directly.
- The `"x"` open losing a race against another writer: only the earlier exists check is driven.
- A malformed result (no `questions`, or a row without `answer`) raises a `KeyError` traceback, not a corrective message. A run always writes both keys.

## Limitations

- The brief's example index `i * len // CALIBRATION_ROWS` never picks the last eligible row (index 38 of 40), which the required test asks for. The draft uses `i * (len - 1) // (CALIBRATION_ROWS - 1)` instead. This fails with a division by zero only if `CALIBRATION_ROWS` were 1.
- An `answer.found` row whose judge gave no verdict is still eligible, as the brief defines eligibility. That is right for blind grading, since the human grade does not depend on the judge.
- `npm run check:all` and the whole backend suite were not run here; the main session runs `check:all` once for the phase.
