## Old vs new

| Behaviour | Before | After |
|---|---|---|
| Token accounting | `embed` and `draft_answer` discard `response.usage` | Each embedding batch adds `prompt_tokens` to `USAGE["embedding_input"]`; `draft_answer` (when `parse` returns) and `judge` add `prompt_tokens` / `completion_tokens` to `<kind>_input` / `<kind>_output`; a `None` usage adds 1 to `responses_without_usage` |
| Faithfulness judge | none | `await llm.judge(question, answer, passages)` sends the plan's system prompt and `Question:` / `Passages:` / `Answer:`, each passage as `[n] <source>\n<text>` under its own `n`, to `chat.completions.parse` with `model=settings.judge_model()`, `response_format=Verdict`, `reasoning_effort="low"`, and no temperature, top_p, seed or max tokens |
| Judge failures | none | A `None` parse raises `VerdictError` naming the model and the refusal. `LengthFinishReasonError` and `ContentFilterFinishReasonError` raise `VerdictError` naming the model and the error class, after counting the tokens on `.completion` (a missing completion counts as `responses_without_usage`). Every `openai.APIError`, `BadRequestError` included, propagates unchanged |
| `JUDGE_MODEL` | not read | `settings.judge_model()` returns `JUDGE_MODEL` or `gpt-6.1-sol`; `test_config.py` pins the key and the default against `.env.example` |
| Source label | private `llm._source(hit)` | public `llm.source_label(hit_or_citation)`, same output; its only reader, `draft_answer`, updated |
| Test fakes | `fake_embed`, `fake_draft` | plus `fake_judge`: `.reply` (a `Verdict`, or an exception it raises) and `.calls` of `(question, answer, passages)` |

`test_llm_judge.py` (10 tests) covers:

- `test_the_judge_gets_only_the_given_passages_with_their_numbers`: passages numbered 2 and 4; the whole user message is pinned, so an extra passage, a renumbering or a format change fails.
- `test_the_judge_request_uses_the_judge_model_low_effort_and_no_sampling_knobs`: `JUDGE_MODEL` set through the environment reaches `model`; `reasoning_effort == "low"`; `response_format is Verdict`; the system message is `JUDGE_SYSTEM`; no `temperature`, `top_p`, `seed`, `max_tokens` or `max_completion_tokens`; `Verdict`'s fields are `rationale` then `grade`.
- `test_usage_counts_every_embedding_batch_the_answer_and_the_judge`: `EMBED_BATCH = 2` over 3 texts gives 2 embedding calls and `embedding_input == 3`, so both batches count; then a draft and a verdict; `USAGE` equals the exact `Counter`.
- `test_a_response_without_usage_is_counted_as_such`.
- `test_a_refusal_is_a_verdict_error_and_its_tokens_still_count`.
- `test_a_length_or_content_filter_stop_is_a_verdict_error_and_its_tokens_still_count`, for both SDK errors.
- `test_an_api_error_propagates_unchanged`, for `APIConnectionError` and `BadRequestError`, checked by identity. Requests are built with `httpx2`, the HTTP module the openai SDK 3.24 imports.
- `test_fake_judge_records_each_call_and_raises_an_exception_reply`.

## Limitations

- `draft_answer` counts usage only when `parse` returns. A `LengthFinishReasonError` or `ContentFilterFinishReasonError` from the answer call still propagates as P1 left it, uncounted and neither a `VerdictError` nor an `openai.APIError`. Task 2.1 should decide how the run classifies it (it is an `openai.OpenAIError`).
- `VerdictError` messages name the model and the SDK error class, not a corrective action: the run records them per row, and the calibration run is where a judge that fails often shows up.
- `npm run check:all` was not run; the main session runs it once for the phase.
