## Old vs new

| Behaviour | Before | After |
|---|---|---|
| `/` | "LoreOS" placeholder | Opens the first workspace, or `/login` on a 401 |
| Error response with no JSON body (plain-text 500 or 503) | n/a | `ApiError.detail` is the status text, or "Request failed with status N" when the status text is empty (HTTP/2) |
| `Retry-After` | n/a | Read as a number; null when the header is missing or not a number |
| Login gets a 401 or 429 | n/a | Shows the server's detail; a 429 shows "Too many login attempts. Try again in 10 minutes." |
| Signup or invite with an 11-character password | n/a | Refused before any request is sent; the check counts characters the way the server does |
| Invite | n/a | Token read from `location.hash` and sent in the body. Logged out, it posts `{token, email, password}`; logged in, it posts `{token}` and opens the workspace just joined |

## Limitations

- **No visual check.** I took no browser screenshot; the visual layout is the spec's manual row in phase 7. The design stays within the neutral theme tokens: left-aligned auth pages with a large wordmark, and a single header bar for the shell.
- **No health function.** `GET /api/health` has no client function because no screen calls it.
- **Session expiry mid-use.** The Shell checks the session only when it mounts. If a session expires while someone is using Documents, Ask or Settings, those screens (5.3 to 5.5) need to send a 401 to `/login` themselves.
- **Existing users accepting an invite while logged out.** The page tells them to log in, then reopen the link. Login lands on their first workspace, so the invite does not carry through on its own.
- **Commit trailer.** Per AGENTS.md and the memory rule, the commit has no attribution trailer, even though the session reminder asked for one.

## Findings outside the owned files

- **`frontend/src/test-setup.ts` (main session).** vitest runs without `globals`, so Testing Library's automatic cleanup is never registered. Any test file with more than one render needs `afterEach(cleanup)`; I added it to my files. 5.3 to 5.5 will hit the same problem; one `afterEach(cleanup)` in `test-setup.ts` would fix it for every file.
- **`docs/sdd/p4-platform-shell/plan.md`, 5.1 handoff row (main session).** It names `src/lib/utils.cn`, but `src/lib/` does not exist; the components import `cn` from the `cn` package. The row is out of date.
- **Auth routes, task 4.2.** FastAPI's default 422 for a request that fails validation (for example a bad email) returns `detail` as a list, not the contract's string. `api.ts` then shows the status text ("Unprocessable Entity"). The routes should return a string detail on 422, as the contract says.
