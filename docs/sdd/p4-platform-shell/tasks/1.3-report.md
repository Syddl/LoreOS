**What the checks do NOT exercise:**

- The negatives prove `problems()` reports each break. They do not prove that `problems() == []` makes isolation hold.

## Limitations

- **`exists` has no drop test.** Its negative renames `loreos_app` in a rolled-back transaction. Dropping the role is never tested, because other checkouts' databases hold grants to it.
- **Cluster-wide roles across worktrees.** The SET-option case creates a role named `loreos_rls_probe`, and the `alter role` cases lock `loreos_app`. Both are rolled back, so a concurrent run in another checkout waits briefly rather than failing.
- **Postgres 16 or later.** `pg_has_role(..., 'SET')` needs it. On Postgres 15 the assertions query fails with an error instead of reporting a problem. The migration's `with set true` needs 16 or later already.
- **Small extensions beyond the brief:**
  - **`rights`** covers every `loreos` table except `documents` and `chunks`. That includes the brief's seven tables and matches the spec's "on `documents` and `chunks` only". It also counts column-level grants (`has_any_column_privilege`).
  - **`owner`** uses `pg_has_role(loreos_app, relowner, 'USAGE')`. A role that inherits from an owner counts as an owner, which is the case RLS exempts.
  - **Checks are split** so each negative has its own name: exists, login, bypassrls, superuser, owner, rights, dml, rls, policy, set_option, schema, vector_schema.
  - **The role pattern also catches `set local role` and `set session role`.**
  - **The "workspace unset" case also runs with `''`.** That proves the policy's `nullif`.

## Findings outside the owned files

- **`docs/sdd/p4-platform-shell/plan.md` 1.3 (planner):** the negative `grant testdb_owner to loreos_app` fails as written. Postgres answers `role "testdb_owner" is a member of role "loreos_app"`, because the migration grants `loreos_app` to `testdb_owner` and Postgres refuses a membership loop. The test case therefore runs `revoke loreos_app from testdb_owner cascade` first and expects `{owner, rights}`. On Supabase the same loop blocks granting `postgres` to `loreos_app` while `postgres` holds `loreos_app`. The plan's wording should change to match.
- **`backend/loreos/smoke.py` and `backend/loreos/evaluation/run.py` (later P4 tasks):** both still call `engine()` directly for their cross-workspace reads. `SYSTEM_SESSION_FILES` allows it. Moving them to `system_session()` is a later task's edit.
- **Callers:** ingest, retrieval, answering, the evaluation run and the P1 routes all pass as `loreos_app`. None needed a right the migration does not grant.
