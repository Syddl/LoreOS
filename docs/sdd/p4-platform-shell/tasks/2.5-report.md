# Report: task 2.5 Smoke preflight checks the grants

The smoke preflight now runs the `db:verify-rls` assertions and stops before any OpenAI call when one fails. The new case went red on the old preflight and is green now, and `npm run check:backend` passes. Committed as `9d0f5d3`. Setup worked: the merge fast-forwarded to `656445e` and `uv --directory backend sync --locked` did a real install.

## Files touched

| File | Change |
|---|---|
| `backend/loreos/smoke.py` | edited: in `preflight()`, the migration-head check moved inside the open connection, and `verify_rls.problems(conn)` runs on that same connection. Any problem raises `SystemExit` listing each one and "fix each, then run npm run db:verify-rls". The docstring names the new step. |
| `backend/tests/test_smoke.py` | edited: adds a `listed` fixture (a fake `llm.client` whose `models.list()` records each call) and two testdb cases. The 8 existing cases are unchanged. |

## Old vs new

| Behaviour | Before | After |
|---|---|---|
| `preflight()` when `loreos_app` lacks a grant (e.g. `USAGE` on `extensions`) | prints `preflight: ok` and goes on to OpenAI; the vector cast fails only after the embedding is paid for | exits with `preflight: workspace isolation does not hold:` followed by each problem, then `fix each, then run npm run db:verify-rls`; no OpenAI call |
| `preflight()` with the grants in place | lists models | lists models (unchanged) |
| Error reading the version or the grants | `cannot read the schema version (...)` | `cannot read the schema version or the grants (...)`, with the same fix text |
| Migration not at head | `SystemExit` naming both migrations | same message, now raised inside the connection block. It is a `BaseException`, so `except Exception` does not catch it. |
