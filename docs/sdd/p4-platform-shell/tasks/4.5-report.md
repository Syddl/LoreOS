**How the tests work:**
- **Route list.** FastAPI 0.142.2 keeps each included router as one entry in `app.routes`, so reading `route.path` there raised `AttributeError`. The test flattens the list with FastAPI's own public `fastapi.routing.iter_route_contexts(main.app.routes)`. That gives exactly 15 routes: 14 under `/api/workspaces` plus `/api/me`.
- **Keys.** `sorted(PINNED_ENV)` stands for the keys `settings.py` reads, because `test_schema` already pins that `PINNED_ENV` equals them. The seven names from the plan are added to it.
- **Values.** `off`, `false`, `0`, `1` and empty. Each key and value is set alone through `monkeypatch.context()`, so each one is undone before the next.
- **Requests.** No credentials, Origin set to `ORIGIN`, and a fresh `uuid4` for each path parameter.
- **Client.** It uses `raise_server_exceptions=False`, so a 500 counts as a status and is named instead of being raised.
- **Scan.** Matches `\benviron\b|getenv|\b_env\(` line by line with `splitlines()`. The key is the string literal after `environ[`, `environ.get(` or `getenv(`. A read with no literal key is keyed on its whole stripped line, so a second such read in an allowlisted file is still new.
- **Allowlist.** It is keyed on (file, key) and gives a reason for each entry:
  - `ingest.py`, `OPENAI_API_KEY`
  - `smoke.py`, `npm_config_dry_run`
  - `evaluation/__main__.py`, `for key in os.environ:` (the `npm_config_*` loop)
  - `evaluation/__main__.py`, `npm_config_dry_run`
  - `evaluation/calibration.py`, `INIT_CWD`

## Limitations

- **The scan reads text, not code.** It misses an indirect read (`getattr(os, "envi" + "ron")`, `os.__dict__`) and a read outside `backend/loreos/`.
- **One key per line.** If a line has a keyed read, only that key is recorded. A whole-environment read on the same line, such as `os.environ.get("X") or dict(os.environ)`, would slip through as just `X`.
- **Old entries are not flagged.** If an allowlisted read is removed, its entry stays and nothing complains.
- **Only the five values are tried.** A switch that opens on some other value, such as `yes` or `disabled`, is caught by the scan, not by the request pin.
