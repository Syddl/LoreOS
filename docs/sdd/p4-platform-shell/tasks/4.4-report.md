## Old vs new

| Behaviour | Before (after 4.1) | After |
|---|---|---|
| POST documents with a multipart `file` | 405 | **202** `pending`. A duplicate that is not failed gets **200** with the stored document. A failed duplicate is re-queued with 202. A file over 20 MB gets 413. An unsupported type gets 415, naming the accepted types. A form with no `file` field gets 422. |
| POST documents with JSON `{url}` | 405 | **202**, kind `url`. Submitting the same URL again gets 202 with the same id. A refused or malformed URL gets 422. A row the worker holds gets **409** after about 2 s. |
| POST documents with any other content type | 405 | 415 |
| GET documents, GET documents/{id} | JSON 404 from the fallback | The list, or the document. A missing id, or another workspace's id, gets 404. |
| DELETE documents/{id} | 405 | Owner only, answering 204 or 404. A member or a key gets 403. The delete runs with `set local lock_timeout = '2s'`, and sqlstate `55P03` answers **409** "the document is being processed; try again shortly". Chunks go by cascade. |
| POST ask | 405 | `asdict(answer)` with `text` renamed `answer`, so an extra field such as `retrieval_mode` reaches the JSON. |

## Limitations

These are deliberate value changes from P1, as the plan allows:
- **Refusal dict.** The empty-workspace refusal case now compares only P1's four keys instead of the whole dict. Exact equality would break once P3 adds `retrieval_mode`. The exact-equality pin has moved to the extra-field test.
- **Failed duplicate.** As the plan directs, this case now goes through a permanent parse failure, re-queued with `attempts` 0. P1's embed-failure half became its own case: a `ConnectionError` is classed transient, so after `drain()` the row is `pending`, `attempts` 1, error `embed: transient: ConnectionError: upstream timed out`.

Other limitations:
- **Duplicated timeout string.** `'2s'` now appears in both `ingest.py` and `routes/documents.py`. A shared constant would need an edit to `ingest.py`, which this task does not own.
- **Malformed multipart.** A malformed body, or more than one file, gets Starlette's 400 from `request.form(max_files=1)`, not 422. No test covers it.
- **Uploads by key.** A key can upload (it acts as a member), but only key list, ask and the delete 403 are tested.
