# Known gaps

Gaps accepted for now. A row leaves this table when its fix merges (link the PR or the decision) or when a decision rejects it.

| Gap | Impact | Owner | Trigger to fix |
|---|---|---|---|
| The spend guard matches command text. It asks for: <ul><li>`paid:*` in any runner, under any runner file name (npm and its abbreviations, pnpm, yarn, bun, node --run, npm-cli.js, a quoted path, any flags);</li><li>a Python interpreter or uv whose command mentions loreos and a paid module (worker included), even as a `-c` one-liner;</li><li>`docker compose` or `docker-compose` with `up`, `start`, `restart`, `run` or `watch`, except an `up` that starts only `testdb`;</li><li>curl, wget, httpie or Invoke-RestMethod/WebRequest naming `/api` or port 8000.</li></ul>All of these are also caught inside quotes, blocks, pipelines, `$(...)`, `bash -c`, `cmd /c` and `pwsh -c`. No form is exempt, `--dry-run` included. Not asked: <ul><li>a one-liner that posts with its own HTTP library (Python, Node) without naming a loreos module;</li><li>a script file;</li><li>a URL, port, script name or compose command held in a variable;</li><li>the dev API on another port with an encoded path;</li><li>`docker run` of the image through a shell;</li><li>`docker start` or `docker restart` of an existing worker container (compose sets the worker's `restart: "no"`, so Docker itself never starts it);</li><li>PowerShell backtick escapes inside a name (``pa`id``);</li><li>`Start-Process`;</li><li>`eval` of built-up text.</li></ul> | An unapproved post to the running dev API bills one embedding batch per upload, or one embedding plus one answer per question, a fraction of a cent each. A worker started unasked embeds every queued document | backend | A new paid route or entry module, or a session that spends through one of these spellings |
| Expired sessions, used or expired invites, and old `rate_limits` windows are never pruned | The three tables grow by one row per login, invite and rate-limit window; expired rows are refused, never served | backend | Any of them passing about 100k rows, or P6's per-request limits |
| Behind compose, or any proxy, without `FORWARDED_ALLOW_IPS`, every client shares the proxy's address, so the 20-per-15-minutes login bucket per IP is shared too | Anyone who reaches the login page can lock out every login for 15 minutes with 20 wrong passwords. The precondition is a deployment reachable beyond one person | backend | Serving beyond 127.0.0.1: set `FORWARDED_ALLOW_IPS` to the proxy's own address, never `*`, which would let a spoofed `X-Forwarded-For` rotate the bucket |
| No connection cap: the api opens a connection per session, and a burst beyond Supavisor's client limit fails | Those requests get a 500; nothing is lost or half-written | backend | Users report 500s under load, or a deployment expects more concurrent users than the pooler's client limit (recorded in `docs/sdd/p4-platform-shell/STATUS.md`) |
| No route changes a member's role, so a workspace's first owner stays its only owner and cannot hand it over | An owner who leaves cannot pass the workspace on; the operator can change `loreos.memberships.role` by hand | backend | An operator asks for a handover (the P4 plan's "What this plan does NOT cover") |
| The reranker takes about 2.1 s of CPU per question on the dev machine (decision 0010). Reranks run in their own pool of 2 threads (`retrieval.RERANK_POOL`), so on `POST /ask` from any member or API key, a burst of questions queues | Each queued question waits for the reranks ahead of it. Logins and the other routes do not wait: argon2 keeps asyncio's default pool | backend | More than a few concurrent askers, or p95 search time past what users accept: size the pool to the host, or set `RERANK=off` |
| Whether the planner uses the `chunks_tsv` GIN index under `loreos_app`'s RLS policy is unproven: at 922 chunks it seq-scans (17 ms) | Keyword search time grows with a workspace's chunks if the index is skipped | backend | A workspace past about 50k chunks, or keyword search time showing in the search p50 |
| Keyword search ranks heading words like body words, so sibling sections that share a heading path outrank the answer; fused with equal weight, that made `hybrid` worse than `vector` (decision 0010) | None while `hybrid_rerank` serves; the reranker reorders them. `RERANK=off` serves `vector` for that reason | backend | Tuning keyword search or RRF, measured as its own phase |
| A URL document's `sha256` is the hash of its normalised URL, so a `.txt` upload whose bytes are exactly that URL collides with it | The upload comes back as the URL document, a duplicate | backend | A user reports it; hash URLs with a prefix |
| Evaluation workspaces (`eval-<key>`) are never pruned: each new key (a chunker, chunk-size, corpus or embedding-model change) leaves the old workspace, about 10 MB of documents, chunks and vectors | Database space on Supabase grows with every P3 configuration tried | backend | The database nears its plan's size limit. The other trigger, P3's chunk sweep, fired on 2026-10-14: the database is 93 MB, and the operator chose to keep the three unused `eval-*` workspaces (`docs/sdd/p3-hybrid-search/STATUS.md`) |
| Hugo shortcodes in the handbook corpus (`{{% panel %}}`, `{{% details %}}`, `{{< youtube >}}`) stay in chunk text, and text after a closing `details` stays under the heading inside it | Noise in embeddings and in keyword search, as for a user who uploads the same files | backend | P3's keyword search, if shortcode tokens show up among false hits |
| `ANSWER_MODEL` defaults to `gpt-5.4-mini`, a previous generation; its sibling `gpt-5.4-nano` is deprecated | A future deprecation breaks answers until the default changes; every result file records the model it used | backend | OpenAI announces a deprecation date for `gpt-5.4-mini`, or a change to the answer model is weighed in an evaluation |
| `eval/results/` is protected from the edit tools only. A shell copy can still place a scratch result there | A hand-placed result could be committed. `check:backend` fails on a committed result whose `destination` is not `results` or whose judge agreement is null, which catches a copied scratch file but not a forged one | backend | A result file is committed that the run did not write |
| The guard matches `protected_paths` by the path's text. On Windows, other spellings name the same file and are not matched: a different case (`eval/Results/`, `eval/Questions.jsonl`, `.ENV`), a trailing dot or space, or an `::$DATA` stream. A probe confirmed each for `eval/questions.jsonl` and `eval/results/`. This holds for every protected path, `.env` and `.claude/harness.json` included | An agent that respells a path (which AGENTS.md forbids) can edit the evaluation set or the human grades, or write into `eval/results/`, without an ask. The guard is a tripwire, not a sandbox | harness library (`core/guard.mjs`; `.claude/hooks/guard.mjs` is generated from it) | The next guard update from the harness library: fold case, and strip trailing dots, spaces and `:` streams on Windows before matching |
| Codex adapter installed, but its hooks are not yet trusted in the Codex CLI | Codex sessions run unguarded until trusted through `/hooks` | operator | The first Codex session in this repo |

Rules for this table:

- One row per gap. Facts, not narrative. No dates in a row; the git log has them.
- A gap with a fix in flight points at `docs/sdd/<feature>/STATUS.md`, not at a branch name.
- A security gap names the surface and the precondition under which it is exploitable.
- A gap that costs money when hit says how much per occurrence.
